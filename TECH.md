# Технологии Motion Playground — что используется и на что это влияет

Документ описывает стек проекта: зачем нужен каждый слой, что именно он делает в приложении
и что сломается, если его убрать. Проект сделан **без внешних зависимостей в коде**:
весь фронтенд — это нативные браузерные API, весь бэкенд — стандартная библиотека Python.

```
Браузер                              Сервер (Python stdlib)
┌──────────────────────────────┐     ┌──────────────────────────────┐
│ index.html + styles.css      │     │ http.server (потоки)         │
│ ES-модули js/**              │◄───►│ WebSocket (ручной RFC 6455)  │
│ Canvas 2D, Web Animations,   │ WS  │ SSE (запасной канал)         │
│ WebAudio, Web Speech,        │ SSE │ REST /api/*                  │
│ MediaRecorder, WebRTC,       │ HTTP│ Прокси внешних API + кэш     │
│ PointerEvents, ImageData     │     │ uploads/ (медиа), data/*.json │
└──────────────────────────────┘     └──────────────────────────────┘
          │        ▲                              ▲
          │        └── сигналинг звонка ──────────┘
          └── медиа-потоки звонка идут напрямую между браузерами (P2P)
```

## 1. Языки и разметка

| Технология | Где | Зачем | Если убрать |
|---|---|---|---|
| **HTML5** (`index.html`) | вся разметка: сцена, панели, модалки, экран входа | семантика, доступность (`role`, `aria-*`), встроенные элементы `<video>`, `<canvas>`, `<input type=file>` | приложения нет |
| **CSS3** (`styles.css`) | темы, сетки, анимации, адаптив | 8 тем через CSS-переменные, `clip-path` для фигур, `grid`/`flex`, медиазапросы | интерфейс без тем, без адаптива; фигуры придётся рисовать на canvas |
| **CSS-переменные** (`--accent`, `--stage-bg`, …) | темы и размеры | смена темы — это смена одного класса на `<body>` | темы придётся переключать перезагрузкой стилей |
| **CSS 3D-трансформации** (`transform-style: preserve-3d`) | `js/scene/model3d.js` | куб, пирамида, призма, цилиндр, сфера, додекаэдр, тор, кость, кубик Рубика без WebGL | 3D-режим останется только на Three.js (а он грузится из сети) |
| **`clip-path: polygon()`** | `js/scene/shapes.js` | все 2D-фигуры + плавный «морфинг» (все фигуры — полигоны с одинаковым числом точек) | фигуры только прямоугольниками/картинками, морфинг невозможен |
| **Медиазапросы** до 320 px | `styles.css`, блоки `max-width: 400px / 340px` | работа на экранах 4 дюйма (iPhone SE, старые Android): одноколоночные панели, прокрутка вкладок, кнопки ≥32 px | на маленьком экране появляется горизонтальная прокрутка и «микро»-кнопки |
| **JavaScript ES2022, модули** | `js/**`, `<script type="module">` | разбиение на core / scene / net / ui / features; никакой сборки | один огромный файл, сложнее поддерживать |
| **Python 3.10+** | `room_server.py` | сервер комнат без зависимостей | многопользовательский режим не работает |

## 2. Браузерные API (фронтенд)

| Технология | Где | На что влияет | Примечание |
|---|---|---|---|
| **Web Animations API** (`element.animate`) | `js/scene/animations.js` | 20 анимаций, их комбинирование, скорость, пауза/старт | `composite: 'add'` позволяет складывать анимации, не перезаписывая друг друга. Fallback: CSS-анимации (медленнее, хуже управляются) |
| **Canvas 2D** | `js/scene/effects.js`, `js/net/whiteboard.js`, `js/scene/cursorfx.js`, `js/features/audio.js`, `js/net/qr.js` | снег/дождь/листопад/конфетти и т. д., общая доска, шлейф курсора, визуализатор микрофона, QR-код | без canvas нет эффектов, доски, визуализатора; QR пришлось бы брать библиотекой |
| **`requestAnimationFrame`** | `js/scene/objects.js`, `physics.js`, `effects.js` | плавные траектории, физика, частицы | при `setInterval` — рывки и лишняя нагрузка на батарею |
| **Pointer Events** | перетаскивание объектов, вращение 3D, доска | одна логика для мыши, пальца и пера | без них пришлось бы дублировать mouse/touch-обработчики |
| **ResizeObserver** | сцена, доска, эффекты | холсты подстраиваются под размер сцены | при изменении размера окна рисунок «поедет» |
| **IntersectionObserver / matchMedia** | там, где нужно ленивое включение | экономия ресурсов | — |
| **Web Audio API** | `js/features/audio.js` | звуки интерфейса, реакция на микрофон | без него звук только через `<audio>`-файлы (а файлов в проекте нет) |
| **`getUserMedia`** | микрофон-визуализатор | спектр голоса управляет масштабом объектов | нужен HTTPS или localhost |
| **Web Speech API** (`SpeechRecognition`) | `js/features/voice.js` | голосовое управление («снег», «тема океан», «стоп») | работает в Chrome/Edge; в Safari/Firefox — кнопка просто предупреждает |
| **MediaRecorder + `canvas.captureStream()`** | `js/net/whiteboard.js` | запись рисования на доске в .webm/.mp4 | Safari старше 14.1 не умеет — показываем предупреждение, остаётся повтор рисунка и скриншот |
| **`canvas.toDataURL()`** + скачивание через `<a download>` | скриншот сцены | PNG со фоном, эффектами и доской | чужая картинка «загрязняет» холст — тогда фон рисуем цветом |
| **Geolocation API** | `js/features/weather.js` | кнопка «📍 Моё место» | без разрешения — ввод города руками |
| **Notifications API** | `js/net/session.js` | уведомления о сообщениях и событиях комнаты | без разрешения — только тосты |
| **Document Picture-in-Picture** | `js/ui/view.js` | окно-в-окне со сценой | только Chrome 116+; проверяем `documentPictureInPicture` |
| **Fullscreen API** | `js/ui/view.js` | полноэкранный и презентационный режимы | — |
| **DeviceOrientation** | `js/features/gestures.js`, `model3d.js` | управление наклоном телефона | на iOS нужен запрос разрешения |
| **localStorage / sessionStorage** | `js/core/store.js` | автосохранение сцены, язык, погода, достижения | без них настройки теряются при перезагрузке |
| **Service Worker + Web App Manifest** | `sw.js`, `manifest.webmanifest` | офлайн-запуск оболочки, установка как приложение | без SW при отсутствии сети приложение не откроется |
| **`<iframe>` вставки YouTube / Rutube / VK** | `js/core/media.js`, `js/scene/backgrounds.js`, `js/scene/preview.js` | видео-фон и объект-видео по ссылке, видны всем участникам комнаты | ссылки не открылись бы — только прямые файлы |
| **`URL.createObjectURL` / FileReader** | загрузка картинок и видео | локальные файлы как фон и объекты | файлы больше лимита остаются локальными (не уезжают в комнату) |
| **`MediaRecorder` + `canvas.captureStream`** | `js/scene/recorder.js` | запись **всей сцены** (фон, эффекты, объекты, доска) в видео: кадры рисуются в отдельный canvas, с которого снимается поток | в старых Safari недоступно — остаются GIF и экспорт CSS/HTML |
| **`getImageData` / `putImageData`** | `js/scene/recorder.js`, `js/features/powder.js` | покадровый сбор GIF и отрисовка песочницы: пиксели пишутся напрямую в `Uint32Array` (одна запись на пиксель вместо четырёх) | без доступа к пикселям нет ни GIF, ни песочницы |
| **Второй canvas как слой свечения** | `js/features/powder.js` | огонь, лава, ток и неон светятся: слой в масштабе клеток размывается `ctx.filter = 'blur(3px)'` и накладывается режимом `lighter` | свечения не будет, огонь будет «плоским» |
| **`new Function` как песочница плагинов** | `js/core/plugins.js` | плагин получает объект `motion`; имена параметров (`window`, `document`, `fetch`, `eval`, …) перекрывают глобальные объекты, поэтому внутри плагина их нет (проверено тестом) | полноценную изоляцию даёт только `<iframe sandbox>`/Worker, но он тяжелее и не даёт доступа к сцене напрямую |

## 3. Сеть и протоколы

| Технология | Где | На что влияет |
|---|---|---|
| **WebSocket (ручная реализация RFC 6455)** | `room_server.py` (`/ws`), `js/net/transport.js` | основной канал: мгновенная доставка состояний, чата, курсоров, доски. Поддержаны ping/pong, кадры 126/127, фрагментация |
| **SSE (`text/event-stream`)** | `/api/events` | запасной канал, если WebSocket закрыт прокси/антивирусом |
| **REST (`fetch` + POST)** | `/api/join`, `/api/message`, `/api/room`, `/api/ext/*` | третий уровень отказоустойчивости и точка для внешних данных |
| **Загрузка медиа на сервер** | `POST /api/upload` + `GET /uploads/*` | снимает ограничение 120 КБ на сцену: картинка/видео до 25 МБ лежат на сервере и отдаются по ссылке. Проверяется тип по содержимому и расширению, имя файла очищается, размер хранилища ограничен |
| **Журнал занятия** | `GET /api/journal?room=CODE` | история комнаты (входы, действия, игры, объявления) пишется в `data/rooms.json` и переживает перезапуск; на клиенте — список, копирование и выгрузка в Markdown |
| **Автопереподключение с экспоненциальной задержкой** | `js/net/transport.js` | индикатор «Переподключение…», возврат без перезагрузки страницы |
| **HTTP `Access-Control-Allow-Origin: *`** | `room_server.py` | можно открыть фронтенд с другого порта/устройства |
| **LAN IP + QR-код** | `js/net/qr.js`, `/api/rooms` | вход с телефона по коду комнаты |
| **`ThreadingHTTPServer` + `RLock`** | `room_server.py` | несколько комнат параллельно, без гонок за состояние комнаты |
| **WebRTC (RTCPeerConnection, getUserMedia, getDisplayMedia)** | `js/net/rtc.js` + сигналинг `kind: 'rtc'` | видео/голос и демонстрация экрана между участниками. Медиа идут напрямую (P2P), сервер пересылает только offer/answer/ICE; есть STUN, переподключение и «доезд» новых участников |
| **Общая сцена комнаты** | `js/net/shared.js` + `kind: shared_enable/disable/update` | один «холст» на всех: правки любого участника рассылаются остальным, но каждый может вернуться к своей сцене (состояние сохраняется при переключении) |
| **Мини-игры через сервер** | `kind: game_create/join/leave/move/reset` | шахматы и крестики-нолики с общей доской: правила и проверка ходов — на сервере, клиент рисует доску и подсвечивает легальные ходы |

## 4. Внешние сервисы (с офлайн-запасом)

Все обращения идут **через наш сервер-прокси** (`/api/ext/*`), чтобы не светить ключи
и чтобы при недоступности источника приложение продолжало работать.

| Данные | Основной источник | Запасные | Офлайн-поведение |
|---|---|---|---|
| Погода | **Open-Meteo** (без ключа) | **api.met.no** (Норвежский метеоинститут), **wttr.in** | последний сохранённый прогноз из localStorage + плашка «нет связи» |
| Геокодинг города | Open-Meteo Geocoding | **Nominatim (OpenStreetMap)**; если оба недоступны — wttr.in по названию города | ввод координат вручную |
| Курсы валют | **ЦБ РФ** (`cbr-xml-daily.ru`) | **open.er-api.com** | плашка «курсы недоступны» |
| Криптовалюты | **CoinGecko** | — | пустой блок |
| Цитата дня | Forismatic / Quotable | ZenQuotes | вшитый набор цитат |
| Факт дня | Useless Facts | — | вшитый набор фактов |
| 3D в WebGL | **Three.js с CDN** (динамический `import`) | CSS 3D | сообщение «WebGL недоступен», сцена остаётся на CSS 3D |

Все ответы внешних сервисов нормализуются: погода приводится к кодам **WMO**
(0 — ясно … 95 — гроза), поэтому эффект сцены (снег/дождь/туман/звёзды) одинаков
независимо от того, какой источник ответил.

Прокси кэширует ответы (погода — 10 минут, курсы — 10 минут), поэтому при
одновременной работе класса внешние API «не долбятся» с каждого клиента.

## 5. Форматы данных и алгоритмы

| Что | Где | Зачем |
|---|---|---|
| **JSON** | состояние сцены, сообщения | состояние участника (объекты, фон, эффекты) целиком уезжает в комнату |
| **Data URL (base64)** | картинки и небольшие видео | чтобы медиа передавалось участникам без файлового хранилища |
| **Сжатие картинок на canvas** | `js/core/media.js` | картинка ужимается до ~30 КБ — иначе состояние не пролезет в лимит |
| **Бюджет медиа** (`MEDIA_SYNC_BUDGET = 120 КБ`) | `js/core/store.js` | считаем длину data URL: что не влезло — заменяем на заглушку «медиа только у автора» |
| **WMO-коды погоды** | `room_server.py`, `js/features/weather.js` | единый «язык» погоды для всех источников |
| **Свой QR-кодер (QR-модель 2, EC level M)** | `js/net/qr.js` | генерация кода входа без библиотек; проверен независимым декодером на Python |
| **Собственный кодировщик GIF89a + LZW** | `js/core/gif.js` | сохранение сцены в GIF без библиотек (PIL/numpy в проекте нет): палитра 6×7×6, поиск ближайшего цвета, LZW-сжатие; проверено независимым декодером на Python |
| **Клеточный автомат на типизированных массивах** | `js/features/powder.js` | песочница «Порошок»: 38 элементов, `Uint8Array` для типа/жизни/«что было до искры», обход снизу вверх со сменой направления, чтобы сыпучие и жидкости не «залипали» |
| **Свой шахматный движок** | `room_server.py` (`chess_move`, `legal_moves`) | ходы, рокировка, взятие на проходе, шах/мат/пат, превращение пешки; сервер отдаёт клиенту готовый список легальных ходов, поэтому подсветка возможных ходов не требует движка в браузере |
| **История изменений + склейка** | `js/core/store.js` | Undo/Redo; соседние правки ползунка склеиваются, история не забивается |
| **Кадрирование/маски PNG** | `icons/icon-maskable-512.png` | корректная иконка на Android |

## 7. Чего в проекте сознательно нет

* **npm, bundler, TypeScript** — проект открывается двойным щелчком по серверу, без сборки;
  весь код — ванильные ES-модули, понятные на уроке информатики.
* **База данных** — комнаты живут в памяти процесса, но каждые 15 секунд (и при остановке
  сервера) сбрасываются в `data/rooms.json` атомарной записью через временный файл.
  Этого достаточно для урока, и урок переживает перезапуск сервера.
* **Библиотеки для работы с изображениями** (PIL, numpy) — вместо них свой кодировщик
  GIF на типизированных массивах; для PNG/SVG используется сам браузер (canvas + `toDataURL`).
* **регистрация и пароли** — вход по имени и аватару; роль ведущего получает первый
  вошедший в комнату.
* **Тяжёлые библиотеки** (Three.js, Chart.js, QR-библиотеки) — либо CDN по требованию,
  либо своя реализация, чтобы проект оставался полностью офлайн-совместимым.
